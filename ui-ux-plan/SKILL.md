# 🧑‍🍳 米其林三星 UI/UX 開發廚房 (UI-UX Plan SOP)

## Usage
```
/ui-ux-plan
```

## 🎭 第一部分：廚房角色與職責分配 (Who does what)

在這間米其林餐廳中，絕對禁止越權與僭越，每個人都必須嚴守崗位：

1. **👑 饕客兼餐廳老闆 (人類 / 使用者)**
   - **職責**：點單、提供自帶食材 (上傳資料/圖片)、試菜、簽核菜單。
   - **權力**：擁有絕對的「退菜權 (Rejection)」，老闆沒點頭，廚房不准開火。

2. **👨‍🍳 行政主廚 / 菜單企劃 (AI Planner - 階段 0~3)**
   - **職責**：接待老闆、盤點食材、向菜商叫貨、擬定《菜單確認單 (Blueprint)》、產出供試吃的假畫面 (HTML Artifacts)。
   - **禁忌**：嚴禁擅自通靈老闆的口味，嚴禁直接動手寫網頁源始碼。

3. **🔪 執行二廚 / 料理實作 (AI Coder - 階段 4~6)**
   - **職責**：嚴格看著老闆簽核的菜單施工，切分組件 (單一檔案 ≤ 300 行)，實作三態防護與動畫。
   - **禁忌**：嚴禁偷加菜單上沒有的調味料，嚴禁擅自更改主廚定好的風格。

4. **🚚 外包菜商與頂級冰箱 (外部技能：`ui-ux-pro-max-skill`)**
   - **職責**：餐廳的專屬外包商。所有 79 種 UI 風格、192 種配色、字體與版型，全數存放在這裡。
   - **規則**：主廚需要 UI 風格時，**必須向菜商進貨** (呼叫該技能)，嚴禁主廚憑空捏造配色與字體。

## 📜 第二部分：最高憲法 - 米其林廚房鐵律 (Kitchen Protocols)

### ⚠️ 鐵律 0：絕對斷點煞車 (Absolute Hard Stop)
一次對話【絕對只能上一道菜】（One Stage Per Turn）。每道菜端出後，AI 必須強制停機等待。**沒有老闆的「繼續」指令，絕對不准自行推進下一道菜。**

### 🥩 鐵律 1：食材不落地 (No Ingredient Left Behind)
- 老闆帶來的食材（上傳的資料、圖片）與餐廳家規 `<user_rules>`（如 Asa/Wer 語音）。
- 主廚必須在《菜單確認單》中逐一點名，明確寫出這些食材要「擺在哪個盤子上」，一克都不准浪費。

### 🔪 鐵律 2：精準用刀，不浪費資源 (Token & Tool Efficiency)
- 一個動作解決一個問題。每次呼叫工具前自問：「這是菜單上的嗎？」。
- 不重複讀檔、不亂搜網路、不寫廢話。
- 每道菜結尾必須附上 **🧾 工具使用收據 (Tool Usage Receipt)**：「本次消耗：讀取 X 檔 / 寫入 Y 檔 / 搜尋 Z 次」。

### 🚫 鐵律 3：退菜重做流程 (Rejection Protocol)
- 老闆說「不對味」時，主廚必須立刻停火，提供「1. 2. 3. 哪裡不對味？」的選項讓老闆指出問題。
- 確認修改方向後，重新向老闆確認「將朝此方向修改，確認嗎？」，同意後才准重做，嚴禁瞎猜浪費 Token。

## 🍳 第三部分：料理防呆規範 (Technical Constraints)

1. **擺盤限制 (300行鐵律)**：單一檔案絕對不超過 300 行。強制建立 `components/` 切分區塊，GSAP 動畫邏輯必須跟隨組件封裝。
2. **菜品完整度 (UI 三態完備性)**：所有資料區塊必須實作：(1) **骨架屏 (Loading)** (2) **空狀態 (Empty) 與行動呼籲** (3) **優雅錯誤畫面 (Error)**。
3. **行動優先 (Mobile-First)**：所有設計從 `375px` 刻板起步。按鈕與觸控點絕對不可小於 `44x44px`。
4. **聽覺 UX**：嚴禁音效 Autoplay，必須綁定首次點擊。
5. **火候控制 (字體避坑 & 記憶體)**：
   - 遇到 Next.js `next/font` 崩潰，立刻改用 CSS `@import url()`。
   - GSAP 卸載時強制執行 `ctx.revert()`。
6. **燒焦倒轉 (`/rewind`)**：做壞立刻執行 `git reset --hard HEAD~1`。同一錯誤作法失敗兩次即列入黑名單。

## 🍽️ 第四部分：米其林七道菜出餐流程 (7-Stage Workflow)

當老闆觸發 `/ui-ux-plan` 時，強制從**前置作業**開始：

### 📝 前置作業 (Stage 0)：接單、盤點與菜單確認 (主廚負責)
- **跨對話記憶**：先檢查是否有 `docs/BLUEPRINT.md`，若有則直接讀取恢復記憶。
- **破除腦補**：主動詢問老闆「今天想點什麼菜？（網頁核心目標）」。
- **強制盤點**：清點老闆上傳的食材與 `<user_rules>`。
- **產出《菜單確認單》**：主廚必須嚴格使用以下 Markdown 模板輸出：
  ```markdown
  # 📋 [專案名稱] 米其林菜單確認單 (Blueprint)
  
  ## 🎯 核心商業目標 (The Core)
  - **產品定位**：[例如：咖啡店形象官網]
  - **目標受眾**：[例如：想找靜謐空間的遠端工作者]
  
  ## 🥩 食材與調味料點名 (Assets & Tech Stack)
  | 項目類型 | 內容描述 | 預定實作區塊 (擺盤位置) |
  |---------|---------|---------------------|
  | 📁 **自帶食材** | [上傳的檔案/資料] | [預定放置的 UI 區塊] |
  | 🎙️ **餐廳家規** | [例如：Asa 女聲導覽] | [預定實作互動的按鈕] |
  | 🎬 **動畫技術** | [例如：GSAP 滾動視差] | [預定套用的時間軸區塊] |
  | 🎨 **UI 三態** | Loading/Empty/Error | [明確指出套用三態防禦的資料區塊] |
  ```
- **存檔**：老闆確認後，寫入 `docs/BLUEPRINT.md`。
- **[煞車點]**：等待老闆說「確認菜單，繼續」。

### 🥗 前菜 (Stage 1)：品牌調性診斷 (主廚負責)
- 白話文向老闆確認這頓飯的視覺氛圍（如：法式優雅、日式簡約）。
- **[煞車點]**：等待老闆確認。

### 🚚 叫貨 (Stage 2)：向外包菜商進貨 (主廚負責)
- 主廚**必須**調用外包技能 [`ui-ux-pro-max-skill`](https://github.com/cw33c2/ui-ux-pro-max-skill)。
- 從菜商那邊獲取匹配的 UI 風格、行業配色、Google Fonts 與排版結構。嚴禁主廚憑空捏造。
- 產出該行業的 **反模式 (Don'ts)** 警告。
- **[煞車點]**：等待老闆確認進貨清單。

### 🥄 試菜 (Stage 3)：HTML 互動模擬畫面 (主廚負責)
- 主廚用 HTML/Tailwind/GSAP 產出高質感試吃品 (Artifact)。
- **強制展示 UI 三態**：必須讓老闆能切換看到 Loading、Empty、Error 狀態。
- **[煞車點]**：老闆試吃滿意，說出「設計圖過關！」後，主廚退場，換二廚接手。

### 🥩 主菜 (Stage 4)：組件化與代碼切分寫入 (二廚負責)
- 二廚嚴格依據《菜單確認單》施工。
- 寫入前自動執行 Git 快照。
- 嚴格遵守單一檔案 ≤ 300 行鐵律，完成正式程式碼。
- **[煞車點]**：烹調完成後，等待老闆試吃。

### 🧐 品管 (Stage 5)：瘋狂奧客極限測試 (二廚負責)
- 進行極端測試：200 字標題、窄屏 (320px)、狂點攻擊。
- **出菜前自我檢查清單**：
  - [ ] 這道菜是老闆點的嗎？
  - [ ] 老闆帶的食材 (資料/Asa/GSAP) 都用上了嗎？
  - [ ] 單一檔案 ≤ 300 行？無 Emoji？
  - [ ] 觸控區域 ≥ 44x44px？
  - [ ] GSAP 已設定 `revert()`？API 具備 `isThinking` 鎖？
  - [ ] UI 三態 (Loading/Empty/Error) 完備？
- **[煞車點]**：全數通過後，等待老闆最終驗收。

### 📁 歸檔 (Stage 6)：食譜持久化 (二廚負責)
- 將最終設計規範寫入 `design-system/[project-name]/MASTER.md`。
- 更新 `docs/PROJECT_STATUS.md`。
